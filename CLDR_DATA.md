# CLDR Data Management

This document describes how to update the Unicode CLDR data used by Localize. CLDR data drives all locale-aware formatting, validation, and display functions.

## Directory Layout

```
priv/
├── cldr/                          # Source data (JSON, XML, CSV)
│   ├── bcp47/                     # BCP47 extension key definitions
│   ├── collation/                 # Collation tailoring XML
│   ├── external_sources/          # Script_Metadata.csv, ISO currencies
│   ├── locales/<locale>/          # Per-locale JSON from CLDR production
│   ├── supplemental_data/         # Supplemental JSON and XML
│   └── validity/                  # Validity XML for subtag validation
│
├── localize/                      # Generated data (ETF, read at runtime)
│   ├── locales/<locale>.etf       # Per-locale compiled data
│   ├── supplemental_data/*.etf    # Supplemental compiled data
│   └── validity/*.etf             # Validity compiled data
│
scripts/
├── ldml2json                      # Shell script to run CLDR's Ldml2JsonConverter
├── convert_currency_data.exs      # Currency data extraction
├── extract_collation_tailoring.exs # Collation tailoring extraction
└── extract_unit_data.exs          # Unit data extraction
```

The `priv/cldr/` directory contains raw CLDR source files and is populated by `mix localize.copy_sources`. These files are gitignored (except for a small number of essential files) since they are large (~500 MB) and reproducible from the CLDR repository.

The `priv/localize/` directory contains compiled ETF files that are read at runtime. Locale ETF files are generated by `mix localize.generate_locales` and are gitignored except for `en.etf` (needed for tests). Supplemental and validity ETF files are generated by `mix localize.generate_supplemental` and are committed to the repository.

## Prerequisites

Two external data sources are required:

* **CLDR Production Data** — the pre-built JSON locale files from a CLDR release. Set the `CLDR_PRODUCTION_DATA` environment variable to the path, or place it at `../cldr_production_data`.

* **CLDR Repository** — a checkout of the Unicode CLDR repository (`github.com/unicode-org/cldr`). Set the `CLDR_REPO` environment variable to the path, or place it at `../cldr_repo`.

## Updating to a New CLDR Version

### Step 1: Update source data

Check out the desired CLDR release tag in `$CLDR_REPO` and download the corresponding production data into `$CLDR_PRODUCTION_DATA`.

### Step 2: Copy source files

```bash
mix localize.copy_sources
```

This copies:

* Supplemental JSON and XML files from `$CLDR_PRODUCTION_DATA` and `$CLDR_REPO` into `priv/cldr/supplemental_data/`.

* Collation XML files from `$CLDR_REPO` into `priv/cldr/collation/`.

* Validity XML files from `$CLDR_REPO` into `priv/cldr/validity/`.

* BCP47 XML files from `$CLDR_REPO` into `priv/cldr/bcp47/`.

* External source files (Script_Metadata.csv) from `$CLDR_REPO` into `priv/cldr/external_sources/`.

* Per-locale JSON files from `$CLDR_PRODUCTION_DATA` into `priv/cldr/locales/<locale>/`.

* Test data files from `$CLDR_REPO` into `test/support/data/`.

* The CLDR version string into `priv/localize/version`.

You can copy subsets independently:

```bash
mix localize.copy_sources --supplemental   # Only supplemental + collation + validity
mix localize.copy_sources --locales         # Only per-locale JSON files
```

### Step 3: Generate supplemental data

```bash
mix localize.generate_supplemental
```

This reads the source JSON/XML files in `priv/cldr/` and generates compiled ETF files in `priv/localize/supplemental_data/` and `priv/localize/validity/`.

### Step 4: Generate locale data

```bash
mix localize.generate_locales
```

This reads per-locale JSON from `priv/cldr/locales/` and generates compiled ETF files in `priv/localize/locales/`. Each locale ETF contains pre-built structs for number symbols, number formats, and currency data (via `Localize.Data.LocaleTransformer`), eliminating runtime struct construction.

To generate a single locale:

```bash
mix localize.generate_locales --locale en
```

### Step 5: Run extraction scripts

Some data requires additional extraction from CLDR XML:

```bash
# Extract collation tailoring data
mix run scripts/extract_collation_tailoring.exs

# Extract unit conversion and preference data
mix run scripts/extract_unit_data.exs

# Extract and convert currency data
mix run scripts/convert_currency_data.exs
```

### Step 6: Verify

```bash
mix test
mix dialyzer
```

Review any test failures — they may indicate data format changes in the new CLDR version that require code updates.

## Mix Tasks Reference

| Task | Description |
|------|-------------|
| `mix localize.copy_sources` | Copies raw CLDR source files into the project |
| `mix localize.generate_supplemental` | Generates supplemental and validity ETF files |
| `mix localize.generate_locales` | Generates per-locale ETF files |
| `mix localize.download_iso_currencies` | Downloads ISO 4217 currency codes from SIX Group |
| `mix localize.upload_locale` | Generates a locale and uploads to Cloudflare R2 |

## Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `CLDR_PRODUCTION_DATA` | Path to CLDR production data directory | `../cldr_production_data` |
| `CLDR_REPO` | Path to Unicode CLDR repository checkout | `../cldr_repo` |
| `R2_ACCOUNT_ID` | Cloudflare R2 account ID (upload only) | — |
| `R2_ACCESS_KEY_ID` | Cloudflare R2 access key (upload only) | — |
| `R2_SECRET_ACCESS_KEY` | Cloudflare R2 secret key (upload only) | — |
| `R2_BUCKET` | Cloudflare R2 bucket name (upload only) | — |

## Data Flow

```
CLDR Repository (XML/JSON)
        │
        ▼
  mix localize.copy_sources
        │
        ▼
  priv/cldr/ (source files)
        │
        ├──► mix localize.generate_supplemental ──► priv/localize/supplemental_data/*.etf
        │                                          priv/localize/validity/*.etf
        │
        ├──► mix localize.generate_locales ──────► priv/localize/locales/*.etf
        │
        └──► scripts/*.exs ─────────────────────► priv/localize/supplemental_data/*.etf
                                                   (collation tailoring, unit data, currencies)
```

At runtime, Localize reads only from `priv/localize/`. The `priv/cldr/` source files are not needed at runtime and are not included in Hex packages.
